# Staging Deployment & Database Seeding Guide

How to fully fix the deployed staging demo — and how the pieces fit together so you
know exactly what still depends on a seeded database.

> **Companion doc:** the frontend also ships a **bundled fallback snapshot** of the
> seed documents (`frontend/public/data/documents.json`, generated by
> `backend/scripts/export_documents_bundle.py`). That bundle fixes the **display
> surfaces** (borrower "Supporting Documents" / tracking panel, officer document
> list, the View modal's extracted data) even when the database is empty. This guide
> covers the **complete** fix: seeding the database so **everything** works —
> pipeline runs, chat answers, document PDFs, vector search, and demo-upload.

---

## 1. Why the demo is currently half-broken

A read-only probe of the deployed Atlas cluster showed the app's database
(`leafy_bank_bian`) contains only:

- `loans` — the 5 seed loan applications (BIAN shape, `loansId` = `APP-2026-0000X`)
- `customers` — the shared BIAN party directory (owned by the umbrella accounts service)

It has **no** `documents`, `underwriting_policies`, `payments`, `agent_activity`,
`conversations`, `interventions`, `officers`, `renewals`, or `pipeline_locks`
collections. Every demo feature that reads those collections returns empty:

| Surface | Reads from DB? | Broken on an unseeded DB? |
| --- | --- | --- |
| Borrower documents lists / View modal | Yes (falls back to the bundled snapshot) | **Fixed by the bundle** (except PDF preview) |
| Loan officer document list | Yes (falls back to the bundle) | **Fixed by the bundle** |
| Chat "submitted documents" + DocumentChecklist | Yes | **Broken** until seeded |
| Officer "Atlas Vector Search" (documents) | Yes (`$vectorSearch` on embeddings) | **Broken** until seeded |
| Document PDF preview / download | Yes (serves from disk by filename) | **Broken** until seeded |
| Intervention `demo-upload` (Sarah's paystubs) | Yes (runs Bedrock extraction + embedding) | **Broken** until seeded |
| LangGraph pipeline on newly submitted apps | Yes (doc_verifier, loan_app, `$lookup` aggregation) | Needs a seeded/working DB per run |

So: the bundle makes the demo presentable on an unseeded DB; seeding makes the demo
**actually work** end-to-end.

## 2. Prerequisites

Run these steps **in the deployed environment** (a one-off Kubernetes job or
`kubectl exec` into the backend pod) or from any machine with:

1. **Network access to the deployed Atlas cluster** (the `MONGODB_URI` the backend
   actually uses — check `environment/staging-combined.yaml` `env`/`envSecrets` and
   the K8s secret it references, e.g. `session-temp-kanopy`).
2. **`DATABASE_NAME=leafy_bank_bian`** (already set in the deployed env — verify).
3. **The deployed `COLL_*` collection mapping.** The demo resolves physical collection
   names via env overrides (`COLL_APPLICATIONS`, `COLL_DOCUMENTS`, …) with defaults in
   `backend/db/collections_config.py`. The deployed DB stores loans in `loans`, so the
   deployed env must set `COLL_APPLICATIONS=loans` (and any other remaps) — **confirm
   this matches the deployed env before seeding**, otherwise the seed writes to the
   wrong physical collections.
4. **An active AWS SSO session for Bedrock** (document extraction uses Claude):
   ```bash
   aws sso login
   ```
   An expired token fails **silently** during extraction and produces a "seeded app
   with zero documents" state (see Gotchas).
5. **`VOYAGE_API_KEY`** for multimodal embeddings (already in deployed secrets).

## 3. Steps

```bash
cd backend

# 1) Create the missing collections + indexes (+ Atlas Vector Search indexes).
uv run python -m scripts.create_indexes

# 2) Double-check the mapping before seeding:
#    DATABASE_NAME  -> should resolve to `leafy_bank_bian`
#    COLL_APPLICATIONS -> should be `loans` (matches the deployed DB)
#    COLL_DOCUMENTS  -> should be `documents`
#    (list every COLL_* the env sets and confirm they match the physical names
#     the deployed app reads; see section 2-3)

# 3) Seed the demo dataset (idempotent):
uv run python -m scripts.ingest_pdfs
```

`ingest_pdfs` is guarded by a `seed_complete` flag per application. If an earlier
partial run marked an app complete **without** documents (e.g., Bedrock SSO was
expired), the script detects the "app exists but has zero documents" corruption
state, **deletes that app + its borrowers + credit reports, and re-ingests from
scratch**. You don't need to reset anything manually.

If you are running against an environment where the old snake_case-shape data
exists, `ingest_pdfs` writes through the BIAN storage boundary (`to_storage`), so
the new documents land in the correct BIAN shape.

## 4. Verification

After seeding, confirm each previously-broken surface:

```bash
# Per-collection document counts (BIAN field on documents = applicationId):
#   documents.countDocuments({ applicationId: "APP-2026-00001" }) -> 14
#   documents.countDocuments({}) -> 69   (5 profiles × 14 minus Sarah's missing paystubs)
```

Then via the running app:

1. `GET /api/backend/applications/APP-2026-00001/documents` → returns **14** documents
   (was empty before).
2. Chat: ask the borrower assistant *"what documents do I still need?"* → the
   **DocumentChecklist** populates (all `parsed`/`verified`).
3. Officer → application detail → **document search** returns scored results
   (Atlas Vector Search over embeddings).
4. Document View modal → **PDF preview** renders from the backend.
5. Sarah Williams → missing-`paystubs` intervention → **Upload Pay Stubs** runs
   real extraction + embedding and succeeds.
6. Submit a new borrower application → the pipeline's doc verification + risk
   aggregation (`$lookup` on documents) completes.

Optionally refresh the frontend fallback bundle to match the seeded data:

```bash
cd backend && uv run python -m scripts.export_documents_bundle
# writes frontend/public/data/documents.json (~210 KB, no full embeddings)
```

## 5. Gotchas

- **AWS SSO expiry = silent extraction failure.** If ingestion "succeeds" but a
  profile ends up with zero documents, re-run `aws sso login` and re-run
  `ingest_pdfs` — the script self-heals the zero-documents state.
- **`seed_complete` guard.** Apps already marked `seed_complete` are skipped. Only
  the zero-documents corruption case is auto-recovered by the script. If you change a
  profile's `ADDITIONAL_PROFILES` and want it re-seeded, remove its docs/app or reset
  the flag explicitly.
- **Collection-name mapping.** The seed writes through the same `coll()` +
  `COLL_*` indirection the app reads. A mismatch (`COLL_APPLICATIONS` unset while the
  deployed DB uses `loans`) silently lands data in the wrong collection and the app
  still reads empty. Verify the mapping before and after seeding.
- **Database vs database name.** The probe found a `fsi-agentic-lending` database
  (legacy snake_case data, 69 docs) AND `leafy_bank_bian` (BIAN, loans+customers).
  Make sure you are pointing `DATABASE_NAME` at the one the deployed app reads.
- **K8s egress to Atlas.** The deployed pod must be allow-listed to reach the Atlas
  cluster (SaaS Atlas IP allow-list / VPC peering). A serverSelectionTimeout is the
  symptom.
- **PDFs are on disk, not in Mongo.** `GET /documents/{id}/pdf` resolves the file by
  `filename` from `docs/synthetic data/<profile>/` or `PDF_BASE_DIR`. In a Docker/K8s
  deployment, ensure those PDFs are present in the backend image/volume.

## 6. Summary of the two-part fix

| Part | What it fixes | Ship vehicle |
| --- | --- | --- |
| **Frontend fallback bundle** (`frontend/public/data/documents.json` + `lib/documents.js`) | Borrower/officer document **display** on any database state; View modal extracted data + embeddings preview | frontend commit/PR |
